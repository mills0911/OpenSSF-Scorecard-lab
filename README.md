# OpenSSF-Scorecard-lab
[![OpenSSF Scorecard](https://api.scorecard.dev/projects/github.com/mills0911/OpenSSF-Scorecard-lab/badge)](https://scorecard.dev/viewer/?uri=github.com/mills0911/OpenSSF-Scorecard-lab)

Using previously made lab with OpenSFF Scoring, and Readme Generated by AI



Features
- Insert integers according to binary search tree ordering.
- Track repeated values using a frequency field instead of creating duplicate nodes.
- Print in-order, pre-order, and post-order traversals.
- Reject non-integer input and require a positive number of input elements.
- Release allocated tree nodes when the BST object is destroyed.
Scope: The current program demonstrates insertion and traversal. It does not provide interactive search or deletion of individual values. Duplicate frequencies are tracked internally but are not displayed in the traversal output.

Requirements
- A C++ compiler supporting C++20
- CMake 3.20 or newer
Build and run
From the repository's root directory:
cmake -S . -B build
cmake --build build
On Linux or macOS (with a single-configuration generator):
./build/Lab5

Project structure

├── BST.cpp          # Insertion, traversal, and cleanup logic

├── node.cpp         # Node constructor

├── main.cpp         # Console input and program entry point

Security and quality
This repository is being prepared for an OpenSSF Scorecard assessment and the OpenSSF Best Practices badge. The CMake configuration enables compiler warnings and treats warnings as errors. The application also includes basic integer-input validation and tree cleanup.

For the security lab, the next steps are to run an initial Scorecard assessment, document the findings, address identified issues, and record before-and-after results. Security scores and badge statuses are not claimed until the corresponding services report them.
